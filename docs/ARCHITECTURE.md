# Архитектура Μίδας

## Поток данных

```text
MOEX / Yahoo Finance → цены ─────────────────────┐
RSS / Telegram → разметка → новостные признаки ──┤
Судебные данные → признаки событий ──────────────┼→ расстояния → linear / SNF → HRP
Изображения → VLM / CLIP → отдельный сценарий ───┘

Сохранённый портфель → рецензия / вопросы / панель
Дневные котировки → риски / наблюдения / проверка исходов
История → walk-forward / абляции / исследовательские модели
```

## Контракты

1. Веса назначает детерминированный HRP. Текстовые модели размечают входные материалы
   и объясняют результат; произвольный текст не исполняется как команда.
2. HTTP-клиент моделей допускает только loopback. Temperature равна нулю, seed фиксирован.
3. Сырые снимки неизменяемы: запись другого содержимого по существующему адресу — ошибка.
4. Конфигурация строгая: неизвестные ключи и неверные типы отклоняются.
5. Кэш зависит от модели, промпта, схемы, параметров и исходных данных. Транзиентные
   ошибки разметки не сохраняются как удачный результат.
6. Замороженный прогноз отделён от последующих пояснений и проверки исхода.
7. Исторические признаки учитывают время публикации, первого наблюдения и анализа;
   будущие события не участвуют в обучении прошлого периода.
8. Наблюдения за ценой фиксируют условия до последующих закрытий. Итог после завершения
   или нарушения границы не пересматривается; пересмотр ценовой базы останавливает проверку.

## Исполнение

Веб-сервер слушает `127.0.0.1`, выдаёт локальную сессию и защищает изменения CSRF.
Долгие операции запускаются в дочерних процессах через SQLite-очередь. Дневные прогоны
используют общий файловый lock. Расписание вызывает тот же код, что и ручной запуск.
Проверка наблюдений использует сохранённые котировки и не запускает сетевой сбор.

Python-пакет `portagent` сохранён для совместимости импортов и существующих установок.
Публичная команда и модуль запуска — `midas`; имя устанавливаемого пакета —
`midas-portfolio`. Данные и форматы старых отчётов сохраняют совместимость.
